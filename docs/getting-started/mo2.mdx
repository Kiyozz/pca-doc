# MO2

:::danger[Removed in 5.9.0]
PCA's own MO2 integration was **removed**. PCA no longer scans your mods folder, and the `mo2 instance` setting does nothing.

Run PCA **through** MO2 instead — see below. If the option is still enabled in your settings, PCA shows a warning; turn it off.
:::

## Why it was removed

The integration rebuilt the merged `Data` folder by hand and passed every mod folder to the compiler.
It broke in two ways that could not be fixed from PCA:

- the command line grew with the number of mods and hit the Windows limit — see [Command line is too long](../troubleshooting/command-line-too-long);
- when several mods shipped a script with the same name, the wrong one could be compiled.

Running PCA as an MO2 executable gives it the real virtual file system, which does both correctly.

Using Vortex instead? It needs nothing of the sort, see [Vortex](vortex).

## Run PCA through MO2

1. Open MO2, then the executables dialog (the gears icon).
2. Add a new executable.
   - **Title**: `PCA`
   - **Binary**: the path to `PCA.exe`
   - **Start in**: the folder holding `PCA.exe`
3. Confirm, then start `PCA` from the MO2 launcher dropdown.

PCA now sees `Data` the way the game does, mods included, and no configuration is needed on its side beyond the [usual one](configuration).

:::tip[Several instances]
You can create one entry per instance and pass the configuration on the command line, so each one opens on the right game.
Refer to [Application Parameters](../advanced-features/application-parameters).
:::

## Script extenders and Root Builder

Install SKSE or F4SE **as a mod**, its source scripts included, and let MO2 provide them.
With Root Builder, the loader can live in a mod too.

Those files only exist for the programs MO2 launches. Started on its own, PCA cannot see them: the [Creation Kit report](creation-kit#the-script-extenders-source-scripts-cannot-be-found) warns that the extender's source scripts cannot be found, and any script calling an extender function fails. Start PCA from MO2, and both go away.

:::info[Older MO2 on Windows 11]
Before 5.9.3 (2026.4), PCA could miss files that only live in a mod when MO2 shipped a usvfs older than 0.5.7.1, on recent Windows 11 builds — the compiler saw them, PCA did not. It showed as a wrong SKSE warning, or as `Data\Scripts cannot be created (ENOENT)`. Update PCA.
:::
